# SPEC: Desktop app

The backend (0.5.0) and the browser UI (0.6.0) are released; the desktop packaging (Tauri,
PyInstaller, installer) is the last step before 1.0.0. This file holds the product decisions the
app follows and the packaging plan. The implementation is in [architecture.md](../architecture.md).

## Goal

A desktop app a resident can install, set up and leave running, without editing files or
reading English logs. The engine stays what it is (it wins the 06:00 race unattended); the app
adds setup, settings, a schedule switch, history and an activity log around it.

## Product decisions

- **Where it runs:** desktop only, on the PC that runs MuMu: a React UI talking to a local
  backend on `127.0.0.1`. Phone access (login, firewall) and a phone layout are not planned; the
  packaged window gets a minimum width instead.
- **Screens** ("Vé giấy" design; mockups: https://claude.ai/artifact/9U4RU81bLsyEaD9G6Crapr,
  private; one-screen mockup: https://claude.ai/artifact/MneuR5X7eqr9btwQw1hLYY, private):
  Overview (the status line in the header, the next booking as a ticket or the live steps of
  a run, and the History beside it), Schedule (a dry run that must pass once, then the daily
  switch), Settings (booking | device setup | notification), Guide (static). An app not set up yet (no passed dry run, schedule off, nothing running)
  opens on Welcome once per opening: an introduction, then device setup, booking settings and
  schedule, the same screens as elsewhere.
- **Settings:** the resident picks from ready-made choices only: the slots (13, in booking
  order), the court (S6, S8, S9, S10) and the day (today + 0 to 2). Everything else (times,
  app labels, fallback points, timeouts) is the developer's, in `config.toml`, as are the slot
  and court lists (`ui/src/booking.ts`).
- **Device setup:** the user installs MuMu and the Vinhomes app and logs in (detected, with a
  guide; the app never sees a password). Auto setup does the rest: saves the MuMu folder, sets
  540x1600 at 220 DPI (asks before restarting MuMu), allows wake timers. Every run silently
  starts MuMu, connects ADB, starts the driver, restarts the app and turns off animations.
- **Schedule:** allowed once a dry run passed. The PC must sleep, not shut down, stay signed in
  to Windows, and be plugged in.
- **One run at a time:** the 06:00 run, a dry run, auto setup and command-line runs take the
  lock; no dry run or auto setup from the wake time to 5 minutes after the start; the 06:00 run
  takes over a holder 2 minutes before the start.
- **History:** every run writes to one SQLite database, whoever started it; the UI only reads.
  Everything is kept. The History lists the runs of ten days at a time, newest first, real
  bookings unless "include dry runs" is ticked: what each booked, its stamp (booked n/m,
  partly, none, dry run passed), when and how it started (on schedule or by hand), and each
  slot booked or not with the reason. A run opens in place of the list with its slots, every
  step and the technical log.
- **Language and design:** Vietnamese (default) and English, every string in translation files;
  the UI language is kept in browser storage, never in `config.toml`. Paper look: warm grey
  ground, paper cards, stamp blue for booked, orange-red for failed; Bricolage Grotesque and IBM
  Plex Mono; light only; every text color at WCAG AA (4.5:1).
- **Never slow a booking:** while a run goes on the UI asks the backend nothing per step; data
  refreshes at run boundaries only.

## Packaging (to do, last before 1.0.0)

Version number set when it starts.

1. PyInstaller build of the backend and engine (one `.exe`, no Python needed).
2. Tauri shell with the backend as a sidecar, and a minimum window width. Open choice: the UI
   loads from Tauri's origin, so either the backend serves the built UI or the client gets the
   backend's address and CORS allows it.
3. The schedule runs the installed engine (today: the runner folder's Python).
4. Installer (NSIS or MSI) and a GitHub Actions release build on each version tag.
5. Docs and release.

Verified when a clean Windows user installs the app, completes setup, passes a dry run and books
at 06:00 from the installed app.

## Out of scope

Phone access, Telegram setup, installing MuMu or the Vinhomes app, logging in for the user, a
health check before 06:00, fallback slots or courts, counting the monthly quota.
